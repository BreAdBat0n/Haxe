Что такое externs

Externs — это описание внешнего API (обычно JS-библиотеки) в виде классов Haxe. Они не компилируются в код, а только сообщают компилятору, какие методы и свойства есть у внешнего объекта.

Зачем нужны

  • Типизация при работе с внешними библиотеками
  • Автодополнение в IDE
  • Проверка ошибок на этапе компиляции
  • Нет накладных расходов в рантайме

Пример: описание простой библиотеки

Допустим, в JS есть глобальный объект MyLib с методом greet(name):

// MyLib.hx
extern class MyLib {
  static function greet(name:String):String;
}

Теперь из Haxe можно вызывать:

trace(MyLib.greet("мир"));

Компилятор сгенерирует вызов MyLib.greet("мир") в JS — без лишних обёрток.

Extern для класса с полями

extern class Vector2 {
  var x:Float;
  var y:Float;

  function new(x:Float, y:Float);
  function length():Float;
}

Extern для функции с колбэком

extern class Fetcher {
  static function get(url:String, onDone:String->Void):Void;
}

Extern с необязательными полями

typedef Options = {
  ?method:String,
  ?headers:Dynamic,
  ?body:String
}

Extern для глобальной функции

extern class Console {
  static function log(msg:Dynamic):Void;
  static function error(msg:Dynamic):Void;
}

Extern с @:native

Если имя класса в JS отличается от имени в Haxe, используйте @:native:

@:native("THREE.Scene")
extern class Scene {
  function new();
  function add(obj:Dynamic):Void;
}

Extern с @:jsRequire

Для подключения модуля через require (Node.js):

@:jsRequire("fs")
extern class Fs {
  static function readFileSync(path:String, encoding:String):String;
}

Extern с перегрузкой

extern class JQuery {
  @:overload(function(selector:String):JQuery {})
  @:overload(function(el:js.html.Element):JQuery {})
  function new();
}

Правила

  • extern — класс только описывает API, не содержит реализации.
  • Тела методов не пишутся — только сигнатуры.
  • Поля без инициализации.
  • Extern-классы не попадают в выходной код.
  • Можно описывать глобальные объекты, классы, функции, typedef'ы.
  • Модификаторы @:native, @:jsRequire, @:overload управляют генерацией.

Где брать готовые externs

Многие популярные JS-библиотеки уже описаны и доступны через haxelib:

haxelib install jQueryExtern
haxelib install three.js
haxelib install hxnodejs
haxelib install hxelectron

Установленные externs подключаются через -lib имя в build.hxml.

Пример с jQuery

import jQuery.JQuery;

class Main {
  static function main() {
    new JQuery(function() {
      new JQuery("#btn").click(function(e) {
        trace("клик по кнопке");
      });
    });
  }
}

Пример с Three.js

import three.Scene;
import three.PerspectiveCamera;
import three.WebGLRenderer;

var scene = new Scene();
var camera = new PerspectiveCamera(75, 1.0, 0.1, 1000);
var renderer = new WebGLRenderer();
renderer.setSize(800, 600);

Пример с Node.js (hxnodejs)

import js.node.Fs;

var content = Fs.readFileSync("file.txt", "utf8");
trace(content);

Как писать свои externs

  1. Откройте документацию JS-библиотеки.
  2. Создайте extern class с методами и полями.
  3. Используйте @:native, если имя в JS отличается.
  4. Подключите файл через -cp или положите в проект.
  5. Проверьте компиляцию.

Частые ошибки

  • Забыли extern — компилятор попытается сгенерировать реализацию.
  • Неверное имя — используйте @:native.
  • Не подключена библиотека — добавьте -lib или -cp.
  • Несовпадение типов — проверьте сигнатуры в документации.
